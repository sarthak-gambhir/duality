# Two-Color Patterns

Duality draws everything with exactly two themeable colors, `--fg` (foreground) and `--bg` (background). There are no intermediate shades, no hue variants, and no transparency. This page collects the recurring techniques used to express depth and state within that constraint.

export const Demo = ({ children }) => (
  <ThemeProvider defaultTheme="classic">
    <div style={{ padding: "var(--space-4)" }}>{children}</div>
  </ThemeProvider>
);

## 1. Inversion

The primary tool. Hover, selection, and "filled" surfaces swap the pair so `--fg` becomes the background and `--bg` becomes the text. A solid button is already inverted relative to the page; hovering it inverts again.

<Demo>
  <Inline gap={3}>
    <Button variant="solid">Solid</Button>
    <Button variant="inverse">Inverse</Button>
    <Button variant="ghost">Ghost</Button>
  </Inline>
</Demo>

Implemented with the `du_invert` mixin:

```scss
@include m.du_invert; // color: var(--bg); background-color: var(--fg);
```

## 2. Textured fill (dither / hatch)

A pattern built from the two colors acts as the system's "gray". It marks disabled surfaces and indeterminate/placeholder states (Skeleton, indeterminate Progress, scrims, tracks). Because it is literally the two colors interleaved, it reads as a muted tone without introducing a third value.

The pattern is a single token driven by `data-texture` on the theme root, so it flips between **dither** (default checkerboard) and **hatch** (diagonal lines) across every textured surface at once. Use the **Texture** toolbar control to preview both, or `<ThemeProvider defaultTexture="hatch">`.

<Demo>
  <Inline gap={3}>
    <Button disabled>Disabled</Button>
    <Badge>Enabled</Badge>
  </Inline>
</Demo>

```scss
@include m.du_texture_fill; // dither or hatch, per the active texture
```

## 3. Keeping disabled text legible

Text placed over a texture can lose legibility, so disabled controls get one of two two-color treatments - both keep the text crisp with no blur or intermediate tone:

- **Selection / action controls** (Button, Checkbox, etc.) ring each glyph in `--bg` with `du_text_outline`.
- **Value-entry controls** (Input, Select, DatePicker, etc.) paint the value on a `--bg` text-stroke plate via `du_disabled_field`, so the value stays readable behind the fill whichever texture is active. Disabled value controls can also surface a `disabledReason` in a persistent caption below the field (wired to the control via `aria-describedby`).

```scss
// selection / action control
&:disabled {
  @include m.du_texture_fill;
  @include m.du_text_outline(2);
}

// value-entry control
&:disabled {
  @include m.du_disabled_field; // texture fill + --bg stroke plate behind the value
}
```

Read-only value controls are distinct from disabled: they stay legible and unfilled, marked instead by a lock cell (for example, `Rating` renders a joined lock + rule ahead of the stars).

## 4. Border style, not color

Status and validity change the **border style** rather than the color. Invalid fields use a dashed border; Alert/Banner tones use solid / dashed / double borders plus a differently shaped marker.

## 5. Marker shape

When a status needs an icon, its **shape** carries the meaning (filled square vs. hollow square vs. rotated diamond), never a color. This keeps information intact for users who cannot distinguish the two colors.

## 6. Focus rings

Focus is shown with an outline in `--fg` (or `--bg` on inverted surfaces via `du_focus_inset`), offset from the control. It is additive to whatever other state is present, so focus is always visible.

---

Together these six patterns cover every state in the library without ever reaching for a third color, a hue, or transparency.
