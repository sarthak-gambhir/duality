# Theming and Density

Everything renders inside a `ThemeProvider`, which establishes a theme scope on a `du_theme_root` element carrying `data-theme`, `data-density`, and `data-texture`. The tokens stylesheet reads those attributes to resolve the two colors, the spacing / sizing scale, and the texture fill. Import the stylesheet once:

```tsx
import { ThemeProvider, Button } from "@astrabound/duality";
import "@astrabound/duality/styles.css";

export function App() {
  return (
    <ThemeProvider defaultTheme="classic">
      <Button>Get started</Button>
    </ThemeProvider>
  );
}
```

## Themes

A theme is a single fixed pair of colors (`fg` / `bg`) from which `--fg` / `--bg` resolve. Light and dark are separate named themes rather than a toggle, so each is hand-tuned on its own. Every theme meets AAA (7:1). Preview any of them with the **Theme** toolbar control, or set one as the default:

```tsx
<ThemeProvider defaultTheme="phosphor">...</ThemeProvider>
```

Built-in themes: `classic`, `dark`, `paper`, `slate`, `sepia`, `amber`, `phosphor`, `blueprint`, `teal`, `sakura`. The `palettes` export (and the `contrastRatio` / `meetsAAA` helpers) are available if you want to validate custom pairs. The `PaletteSelect` component is a ready-made theme picker bound to the provider.

Note this is distinct from the per-component inversion used for hover / selected states, which always swaps the two active colors locally.

## Persistence

Pass a `storageKey` to persist the active theme, density, and texture to `localStorage` and restore them on the next load:

```tsx
<ThemeProvider storageKey="duality">...</ThemeProvider>
```

## Density

`density` scales the spacing and sizing tokens without touching the colors or border widths. `comfortable` (default) uses the standard scale; `compact` applies a tighter one via `data-density="compact"`.

```tsx
<ThemeProvider defaultDensity="compact">...</ThemeProvider>
```

`useTheme()` exposes `density` and `setDensity`. Use the **Density** toolbar control to compare the two on any story. Because density is applied at the scope, it affects every component at once; the per-component `size` props are independent and still work.

## Texture

`texture` selects the two-color pattern used to fill textured surfaces: `dither` (default) is a fine checkerboard, `hatch` is a diagonal line pattern. It is applied at the scope via `data-texture`, so it flips every textured surface at once - disabled controls and decorative fills (skeletons, scrims, tracks) alike.

```tsx
<ThemeProvider defaultTexture="hatch">...</ThemeProvider>
```

Disabled value-entry controls (Input, Select, DatePicker, etc.) fill with the active texture and keep their value legible via a `--bg` text-stroke plate painted behind the fill, whichever texture is active. `useTheme()` exposes `texture` and `setTexture`, and the `TextureSelect` component is a ready-made picker bound to the provider. Preview it with the **Texture** toolbar control.

## Reduced motion

When `prefers-reduced-motion: reduce` is set, Duality drops all animations and transitions and falls back to a static two-color equivalent. Nothing is lost, because motion is only ever a secondary cue.

## Right-to-left

Component styles use logical properties throughout, so setting `dir="rtl"` on any ancestor mirrors the layout correctly. Preview it with the **Direction** toolbar control.

## Portaled overlays

Overlays that portal out of the DOM flow (`Modal`, `Drawer`, `Toast`, `ConfirmDialog`, `ContextMenu`) render into the nearest theme root via `usePortalContainer`, so they always inherit the active theme and density.
